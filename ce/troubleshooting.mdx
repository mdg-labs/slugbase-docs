## Quick checks

Before diving into specific symptoms, confirm the basics:

1. The instance URL loads over HTTPS and matches your configured `APP_BASE_URL`.
2. The database is reachable and migrations completed on startup.
3. `SESSION_SECRET` and `ENCRYPTION_KEY` are set (minimum 32 characters each).
4. Browser cookies are allowed for your instance domain.

## Installation and startup

| Symptom | Likely cause | What to do |
|---------|--------------|------------|
| Container exits immediately | Missing required secrets or invalid `DATABASE_URL` | Check logs; set `SESSION_SECRET`, `ENCRYPTION_KEY`, and database URL |
| Setup page loops | Database not empty but no valid admin | Restore from backup or inspect database state |
| "Already configured" on setup | Setup already completed | Sign in normally; setup runs only once |

See [Quick start](/ce/quick-start) for install steps.

## Sign-in and sessions

| Symptom | Likely cause | What to do |
|---------|--------------|------------|
| Redirect loop after sign-in | Cookie blocked or wrong `FRONTEND_ORIGIN` | Allow cookies; align `APP_BASE_URL` and `FRONTEND_ORIGIN` with real URLs |
| Session expires quickly | Default TTL | Adjust `SESSION_TTL_DAYS` if needed |
| Federated sign-in fails | OIDC misconfiguration | Verify callback URL, issuer, and client credentials — see [OIDC](/ce/oidc) |
| MFA code rejected | Clock drift or reused code | Use a fresh code; sync server time (NTP) |

## Email

| Symptom | Likely cause | What to do |
|---------|--------------|------------|
| No invitation or reset email | SMTP not configured or failing | Configure [SMTP](/ce/smtp) environment variables and restart the service; trigger a password reset or member invitation to verify delivery |
| Mail arrives but lands in spam | Missing DNS auth | Add SPF/DKIM/DMARC for the domain in `SMTP_FROM` |
| Cannot change email in workspace settings | Operator-managed mail | Update `SMTP_*` deployment variables instead — there is no SMTP panel in the UI |

## Workspaces and members

| Symptom | Likely cause | What to do |
|---------|--------------|------------|
| Cannot create workspace | Not an instance administrator | Only instance admins create workspaces on CE |
| User has no workspace after sign-in | Not invited | [Invite](/ce/members-and-teams) them into an existing workspace |
| Public signup when unwanted | `PUBLIC_REGISTRATION=true` | Set `PUBLIC_REGISTRATION=false` for invite-only |

## AI suggestions

| Symptom | Likely cause | What to do |
|---------|--------------|------------|
| Suggestions never appear | AI disabled or no API key | Enable in [AI suggestions](/ce/ai-suggestions) |
| Provider timeout | Outbound network blocked | Allow HTTPS egress to your AI provider |

## API and tokens

| Symptom | Likely cause | What to do |
|---------|--------------|------------|
| 401 with API token | Revoked or malformed Bearer header | Create a new [API token](/ce/api-tokens) |
| CSRF error with curl | Using session cookie without CSRF token | Use Bearer tokens for scripts, or fetch CSRF token for cookie auth |

## Upgrades

Deploy a newer container image and restart. Migrations run forward automatically on startup. Take a database snapshot before upgrading production instances.
