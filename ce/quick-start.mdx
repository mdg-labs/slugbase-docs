## What you'll accomplish

After this guide, you will have a running SlugBase CE instance reachable on port `3000`, ready for [first workspace setup](/ce/first-workspace-setup).

## Prerequisites

- A Linux or macOS host (or any environment that runs Docker)
- **Docker** and **Docker Compose** installed and running
- A domain name (or local hostname) for HTTPS in production
- Secrets ready to generate: `SESSION_SECRET` and `ENCRYPTION_KEY` (each at least 32 bytes — for example `openssl rand -hex 32`)

<Callout kind="danger" title="Important">
Never commit real secrets to version control or paste them into documentation. Use a secrets manager or an `env` file with restricted permissions on the host.
</Callout>

## Architecture overview

SlugBase CE uses one **combined image** that serves the API and web client on a single port (default `3000`). PostgreSQL stores all workspace data. A reverse proxy in front of the container terminates TLS and forwards traffic in production.

## Step 1 — Create your environment file

Create `slugbase.env` in your deployment directory. Minimum runtime keys:

| Variable | Purpose |
|----------|---------|
| `SLUGBASE_EDITION` | Edition selector — set to `ce` for Community Edition (required in production; baked into the GHCR image by default) |
| `SESSION_SECRET` | Signs server-side sessions |
| `ENCRYPTION_KEY` | Encrypts sensitive settings at rest |
| `DATABASE_URL` | PostgreSQL connection string — use the Compose service hostname `postgres` |
| `APP_BASE_URL` | Public HTTPS URL users open in the browser |
| `FRONTEND_ORIGIN` | Same origin as `APP_BASE_URL` on the combined image |
| `PUBLIC_REGISTRATION` | `false` for invite-only (recommended default) |
| `EMAIL_VERIFICATION_REQUIRED` | `false` unless you configure SMTP first |

Example `slugbase.env` for a local smoke test (replace secrets and URLs before production):

```bash
SLUGBASE_EDITION=ce
SESSION_SECRET=replace-with-openssl-rand-hex-32
ENCRYPTION_KEY=replace-with-openssl-rand-hex-32
DATABASE_URL=postgresql://slugbase:CHANGE_ME@postgres:5432/slugbase
APP_BASE_URL=http://localhost:3000
FRONTEND_ORIGIN=http://localhost:3000
PUBLIC_REGISTRATION=false
EMAIL_VERIFICATION_REQUIRED=false
```

<Callout kind="tip" title="Optional integrations">
Configure outbound email and federated sign-in through **deployment environment variables** — not the workspace settings UI. See [SMTP](/ce/smtp) and [OIDC](/ce/oidc) when you need invitations, password reset, or SSO. Leave Stripe, Turnstile, and Cloud analytics keys empty — those interfaces are no-ops on CE.
</Callout>

## Step 2 — Run with Docker Compose (recommended)

**Docker Compose is the recommended install path.** It runs PostgreSQL alongside SlugBase with health checks, persistent database storage, and a copy-pasteable stack you can version in your infrastructure repo.

Create `docker-compose.yml` next to `slugbase.env`:

```yaml
services:
  postgres:
    image: postgres:16-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER: slugbase
      POSTGRES_PASSWORD: CHANGE_ME
      POSTGRES_DB: slugbase
    volumes:
      - slugbase_pg:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U slugbase -d slugbase"]
      interval: 5s
      timeout: 5s
      retries: 10
      start_period: 5s

  slugbase:
    image: ghcr.io/mdg-labs/slugbase:latest
    restart: unless-stopped
    env_file: ./slugbase.env
    ports:
      - "3000:3000"
    depends_on:
      postgres:
        condition: service_healthy
    healthcheck:
      test:
        [
          "CMD",
          "node",
          "-e",
          "fetch('http://127.0.0.1:3000/health').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))",
        ]
      interval: 10s
      timeout: 5s
      retries: 12
      start_period: 45s

volumes:
  slugbase_pg:
```

Pull the image and start the stack:

```bash
docker compose pull
docker compose up -d
docker compose ps
```

<Callout kind="tip" title="Pin a release tag in production">
The example uses `ghcr.io/mdg-labs/slugbase:latest` for convenience. In production, pin a specific release tag (for example `ghcr.io/mdg-labs/slugbase:v1.0.0`) so upgrades are deliberate. Snapshot your database before upgrading.
</Callout>

<Tabs>
  <Tab title="docker run">
    For a single-container trial without Compose, provide PostgreSQL separately and point `DATABASE_URL` at it:

    ```bash
    docker pull ghcr.io/mdg-labs/slugbase:latest

    docker run -d \
      --name slugbase \
      --env-file /path/to/slugbase.env \
      -p 3000:3000 \
      --restart unless-stopped \
      ghcr.io/mdg-labs/slugbase:latest
    ```

    Pin a release tag instead of `latest` in production.
  </Tab>
  <Tab title="Behind a reverse proxy">
    Terminate TLS at nginx, Caddy, or Traefik. Proxy HTTPS traffic to `http://127.0.0.1:3000`. Set `APP_BASE_URL` and `FRONTEND_ORIGIN` in `slugbase.env` to your public `https://` URL so cookies and CORS match what users see. You can remove the published `3000:3000` port mapping and expose the container only on the Docker network.
  </Tab>
</Tabs>

The API applies schema migrations automatically on startup.

## Step 3 — Verify health

Confirm the stack is responding:

```bash
curl -sS http://127.0.0.1:3000/health
curl -sS http://127.0.0.1:3000/version
docker compose ps
```

Both HTTP endpoints should return success and the `slugbase` service should report healthy. If the database is unreachable, check `DATABASE_URL`, the `postgres` service health, and that `POSTGRES_PASSWORD` matches the password in the connection string.

## Step 4 — Complete initial setup

Open your public URL in a browser. On a fresh instance you are redirected to **Set up your instance** (`/setup`).

Follow [First workspace setup](/ce/first-workspace-setup) to create the instance administrator and your first workspace.

## Verify it worked

- `/health` and `/version` respond
- `docker compose ps` shows `slugbase` and `postgres` healthy
- The browser shows the setup wizard (first install) or sign-in (if setup already completed)
- After setup, you can sign in and land on **Home**

## Troubleshooting

### Container exits immediately

Check logs with `docker compose logs slugbase`. Missing `SESSION_SECRET`, `ENCRYPTION_KEY`, or `DATABASE_URL` prevents startup.

### Database connection errors

Confirm PostgreSQL accepts connections from the Compose network, credentials in `slugbase.env` match `POSTGRES_*` in `docker-compose.yml`, and the `postgres` service is healthy before `slugbase` starts.

### Redirect or cookie issues behind a proxy

Ensure `APP_BASE_URL` and `FRONTEND_ORIGIN` use the same `https://` hostname users type in the browser. Configure your proxy to forward `X-Forwarded-Proto` and `Host` correctly.

### Setup screen says the instance is already configured

Setup runs once per deployment. Sign in with the administrator account created during setup, or restore from backup if you are rebuilding.
