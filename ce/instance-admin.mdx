## What you'll learn

After reading this guide, you will know what an instance administrator can do, how the role differs from workspace admin, and how to run a CE deployment without a separate operator console.

## Instance administrator role

An **instance-wide administrator** is a user account flagged to govern the entire deployment. This role is distinct from **workspace admin**:

| Scope | Instance administrator | Workspace admin |
|-------|---------------------|-----------------|
| Create workspaces | Yes | No (unless also instance admin) |
| Invite users into workspaces | Via workspace admin flows | Yes, within their workspace |
| Configure SMTP / OIDC / AI credentials | Yes — via deployment env vars | No — operator-managed |
| Enable AI suggestions per workspace | No | Yes — enable toggle only |
| Reset user MFA | Yes (CE recovery path) | No |
| Manage billing | N/A on CE | N/A on CE |

There is **no separate operator console in v1**. Instance administrators use the same SlugBase web application as everyone else, plus deployment-level configuration through environment variables and infrastructure tools.

## First-run setup

When the database has no users, visiting the instance opens a one-time **Set up your instance** flow:

<Steps>
  <Step title="Create the admin account">
    Enter your name, email, and password. This account becomes the instance administrator.
  </Step>
  <Step title="Create the first workspace">
    Name your first workspace and finish setup.
  </Step>
</Steps>

After setup, the setup flow is no longer available.

## Ongoing administration tasks

### Create workspaces and onboard users

Community Edition SlugBase is an **admin-curated multi-workspace** product:

1. Create workspaces from the **New workspace** action in the workspace switcher.
2. Invite members from **Settings → Administration → Members &amp; teams**.
3. Keep **public registration** disabled unless you intentionally want open signup.

### Configure email, identity, and AI

SMTP transport, OIDC identity providers, and the OpenAI credential are **operator-managed on both CE and Cloud**. Configure them through deployment environment variables — not through the workspace settings UI.

| Integration | Environment variables | Guide |
|-------------|----------------------|-------|
| Outbound email | `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | [SMTP](/ce/smtp) |
| Federated sign-in | `OIDC_{SLUG}_CLIENT_ID`, `OIDC_{SLUG}_CLIENT_SECRET`, `OIDC_{SLUG}_ISSUER_URL`, plus optional `NAME`, `SCOPES`, `ENABLED` | [OIDC](/ce/oidc) |
| AI suggestions | `OPENAI_API_KEY`, `OPENAI_MODEL` | [AI suggestions](/ce/ai-suggestions) |

Restart the SlugBase service after changing credential variables. Workspace admins can then enable AI suggestions per workspace from **Settings → Workspace → AI suggestions**.

<Callout kind="alert" title="Breaking change">
Workspace admin UI for entering SMTP passwords, OIDC client secrets, and AI API keys has been removed. Credentials are no longer stored in the database.
</Callout>

### Promote additional instance administrators

Instance admin promotion is performed at the deployment level (database flag on the user account). The first account created at setup is an instance administrator by default.

### Recover locked-out users

If a user loses access to MFA and backup codes, an instance administrator can reset MFA directly — the CE recovery path documented in the product spec.

## Deployment configuration

Operators manage infrastructure settings outside the web UI:

| Area | Examples |
|------|----------|
| URLs | `APP_BASE_URL`, `FRONTEND_ORIGIN` |
| Secrets | `SESSION_SECRET`, `ENCRYPTION_KEY` |
| Database | `DATABASE_URL` |
| Registration | `PUBLIC_REGISTRATION` (default `false` on CE) |
| Email | `SMTP_*` — see [SMTP](/ce/smtp) |
| Identity | `OIDC_{SLUG}_*` — see [OIDC](/ce/oidc) |
| AI | `OPENAI_API_KEY`, `OPENAI_MODEL` — see [AI suggestions](/ce/ai-suggestions) |

See your operator runbook and [Quick start](/ce/quick-start) for install and upgrade procedures.

## What instance admins do not have in v1

- A dedicated super-admin dashboard or account directory UI
- Workspace UI for SMTP, OIDC, or AI credentials
- First-class backup/restore beyond [export](/ce/backup-and-export) and database volume copy
- Cloud-style billing or plan management
