## General

### How is Community Edition different from SlugBase Cloud?

Community Edition runs the same application on your infrastructure. You control data residency, email, identity providers, and upgrades. SlugBase Cloud is a managed service with operator-configured email, OIDC, billing, and infrastructure. Feature limits that apply to Cloud plans (bookmark caps, team gates) do not apply on CE — all workspace features are available.

### What licence applies to Community Edition?

There is no separate commercial licence or dual-licensing workflow in v1.

### Do I need a license key?

No. CE v1 does not require a licence key. The instance uses a no-op billing implementation with full entitlements. There is no paid CE licence in v1.

### Can every user create their own workspace?

No. Community Edition is designed as an **admin-curated multi-workspace** product. Instance administrators create workspaces and invite users. Public registration is off by default; enable it only if you want open signup.

## Workspaces and data

### Can I belong to multiple workspaces?

Yes. One account can be a member of many workspaces with different roles in each. Switch workspaces from the sidebar or command palette.

### What happens to my bookmarks if I leave a workspace?

Your bookmarks, folders, and tags stay in the workspace. Export them first if you need a personal copy. See [Backup and export](/ce/backup-and-export).

### Are slugs public short links?

No. Slugs resolve only for signed-in workspace members. `/go/&lt;slug&gt;` requires authentication and uses your active workspace context.

## Security

### Does CE support MFA?

Yes. Every account can enroll TOTP two-factor authentication from **Settings → Account → Two-factor auth**. API tokens and federated sign-in bypass MFA.

### How are secrets stored?

SMTP passwords, OIDC client secrets, and AI API keys are supplied by the operator through deployment environment variables — they are **not** stored in the database. MFA secrets and other sensitive at-rest values in the database are encrypted via `ENCRYPTION_KEY`. Session signing uses `SESSION_SECRET`.

### Can I use SSO?

Yes. Instance operators configure OIDC identity providers via `OIDC_{SLUG}_*` deployment environment variables. Workspace admins cannot add providers in the UI. See [OIDC](/ce/oidc).

## Email and invitations

### Why are invitation emails not sending?

Outbound email requires SMTP configuration by the instance operator (`SMTP_*` environment variables). See [SMTP](/ce/smtp). After configuring SMTP, trigger a password reset or invitation to verify delivery.

### How long are invitations valid?

Invitation links expire after **7 days**. Workspace admins can resend or revoke pending invitations from **Settings → Administration → Members &amp; teams**.

### Can I disable email verification?

Email verification is configurable on CE (`EMAIL_VERIFICATION_REQUIRED`). SlugBase Cloud requires verification by default.

## Features

### Is team sharing available?

Yes, on all CE workspaces. Share bookmarks and folders with members and teams without a plan upgrade. See [Sharing](/ce/sharing).

### Is the audit log available?

Yes. Workspace admins and owners can view the audit log on CE instances. See [Audit log](/ce/audit-log).

### Are API tokens restricted by plan?

No. Any account can create personal API tokens. See [API tokens](/ce/api-tokens).

### What AI provider does SlugBase use?

v1 uses OpenAI behind a vendor-neutral contract. The instance operator supplies `OPENAI_API_KEY` via deployment configuration; workspace admins enable suggestions per workspace. See [AI suggestions](/ce/ai-suggestions).

## Operations

### Is there a separate admin console?

No dedicated operator console in v1. Instance administrators use the standard web app plus deployment configuration. See [Instance admin](/ce/instance-admin).

### How do I back up my instance?

Use per-user JSON [export](/ce/backup-and-export) for bookmark content and database volume snapshots for full-instance recovery. There is no one-click restore UI in v1.

### How do I upgrade?

SlugBase CE uses two GHCR images — `slugbase-api` and `slugbase-web` — that version independently. Pin semver tags on each image in `docker-compose.yml`, snapshot the database, run `docker compose pull` and `docker compose up -d`, and verify **api** and **web** health. Migrations apply on api startup. See [Quick start](/ce/quick-start) and [Troubleshooting](/ce/troubleshooting).

### Did workspace credential UI go away?

Yes. Workspace settings no longer include SMTP, OIDC, or AI credential forms. Operators configure `SMTP_*`, `OIDC_{SLUG}_*`, and `OPENAI_*` environment variables on the deployment instead. See [SMTP](/ce/smtp), [OIDC](/ce/oidc), and [AI suggestions](/ce/ai-suggestions).
