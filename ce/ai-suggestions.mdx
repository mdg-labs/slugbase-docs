## What you'll accomplish

After this guide, you understand how AI suggestions work on CE: the instance operator supplies the API credential via deployment configuration, and workspace admins choose whether suggestions are enabled for their workspace. Members can opt out individually.

## What AI suggestions do

When enabled for a workspace, SlugBase can suggest bookmark **titles**, **slugs**, and **tags** based on a destination URL (and fetched page metadata). Suggestions appear when you create or edit a bookmark.

AI is optional. Until the operator configures a credential **and** a workspace admin enables suggestions, the feature remains off.

## Operator vs workspace admin responsibilities

| Role | Responsibility |
|------|----------------|
| **Instance operator** | Set `OPENAI_API_KEY` and optional `OPENAI_MODEL` on the deployment |
| **Workspace admin** | Toggle **Enable AI suggestions** in **Settings → Workspace → AI suggestions** |
| **Member** | Optionally opt out in **Settings → Account → Preferences** |

The workspace settings UI does **not** include an API key or model selector. Credentials are operator-managed and are not stored in the database.

<Callout kind="alert" title="Breaking change">
Earlier SlugBase releases allowed workspace admins to enter an OpenAI API key in the workspace settings UI. That credential form has been removed. Set `OPENAI_API_KEY` and `OPENAI_MODEL` on your deployment instead.
</Callout>

## Prerequisites (operator)

- Access to your CE deployment configuration
- An OpenAI API key (v1 uses OpenAI behind a vendor-neutral contract)
- Outbound HTTPS from the SlugBase container to the OpenAI API

### Configure the operator credential

| Variable | Purpose | Example |
|----------|---------|---------|
| `OPENAI_API_KEY` | Deployment-level OpenAI credential | `sk-…` |
| `OPENAI_MODEL` | Chat model for suggestions (optional) | `gpt-4o-mini` |

```yaml title="docker-compose.yml"
services:
  api:
    image: ghcr.io/mdg-labs/slugbase-api:1.0.0
    environment:
      OPENAI_API_KEY: ${OPENAI_API_KEY}
      OPENAI_MODEL: gpt-4o-mini
```

Restart the **api** service after changing these values. Omit `OPENAI_API_KEY` to disable AI entirely.

<Callout kind="danger" title="Important">
Never commit API keys to source control. Inject `OPENAI_API_KEY` via your secrets manager or a local `.env` file excluded from version control.
</Callout>

## Enable suggestions (workspace admin)

<Steps>
  <Step title="Open AI suggestions">
    Go to **Settings → Workspace → AI suggestions** (labeled **AI** in the section navigation).
  </Step>
  <Step title="Enable suggestions">
    Turn on **Enable AI suggestions**. This applies workspace-wide.
  </Step>
  <Step title="Save">
    Click **Save changes**.
  </Step>
</Steps>

If the operator has not configured `OPENAI_API_KEY`, the toggle may be unavailable or suggestions will not appear even when enabled.

## Member opt-out

Individual members can disable AI on their own content from **Settings → Account → Preferences → AI suggestions opt-out**, even when the workspace has AI enabled.

## Verify it worked

1. Confirm the operator has set `OPENAI_API_KEY` and restarted the service.
2. As a workspace admin, enable **Enable AI suggestions** and save.
3. Create or edit a bookmark with a public URL. Suggestion fields should populate after a short delay.

## Troubleshooting

| Symptom | What to do |
|---------|------------|
| No suggestions appear | Confirm the operator has set `OPENAI_API_KEY`, the workspace toggle is on, and outbound HTTPS is allowed |
| Toggle unavailable | Operator has not configured `OPENAI_API_KEY` — see [Instance admin](/ce/instance-admin) |
| Suggestions in wrong language | SlugBase uses the member's language preference for output |
| Member sees no AI | Check whether they enabled **AI suggestions opt-out** in account preferences |
