title: "Configure outbound email (SMTP)"
description: "Set SMTP transport for a SlugBase CE instance via deployment environment variables so verification, invitation, and password-reset email can be delivered."
---

## When you need this

Configure SMTP when your CE instance sends its own email. Without SMTP, flows that depend on email — member invitations, signup verification, password reset, and email-change confirmation — cannot deliver messages.

SMTP transport is **operator-managed**. Instance administrators configure it through deployment environment variables — not through the workspace settings UI.

<Callout kind="alert" title="Breaking change">
Earlier SlugBase releases allowed workspace admins to enter SMTP credentials in **Settings → Workspace → Email / SMTP**. That UI has been removed. Credentials are no longer stored in the database — set `SMTP_*` environment variables on your deployment instead.
</Callout>

## Prerequisites

- Access to your CE deployment configuration (Docker Compose, Kubernetes secrets, or equivalent)
- SMTP server hostname, port, username, and password from your mail provider
- Outbound network access from the SlugBase container to your SMTP server

## Configure SMTP

Set the following environment variables on the SlugBase service. Omit `SMTP_HOST` entirely to disable outbound mail (the application degrades gracefully).

| Variable | Purpose | Example |
|----------|---------|---------|
| `SMTP_HOST` | SMTP server hostname | `smtp.example.com` |
| `SMTP_PORT` | SMTP port | `587` |
| `SMTP_SECURE` | Use implicit TLS (`true`/`false`) | `false` |
| `SMTP_USER` | SMTP authentication username | `mailer@example.com` |
| `SMTP_PASS` | SMTP authentication password | `<app password>` |
| `SMTP_FROM` | Sender address for transactional mail | `SlugBase <noreply@example.com>` |

<Callout kind="danger" title="Important">
Never commit real SMTP passwords to source control or paste them into documentation. Use your provider's secret store or environment injection. Rotate credentials if they are exposed.
</Callout>

### Docker Compose example

```yaml title="docker-compose.yml"
services:
  slugbase:
    image: ghcr.io/mdg-labs/slugbase:latest
    environment:
      SMTP_HOST: mail.example.com
      SMTP_PORT: "587"
      SMTP_SECURE: "false"
      SMTP_USER: mailer@example.com
      SMTP_PASS: ${SMTP_PASS}  # inject via .env or secrets manager
      SMTP_FROM: "SlugBase <noreply@example.com>"
```

Restart the SlugBase service after changing these values.

## What workspace admins see

Workspace admins and owners do **not** edit SMTP settings. In **Settings → Workspace**, the **Email / SMTP** section shows **Email managed by operator** with a short notice to contact the instance operator for changes.

## What SMTP enables

| Message type | When it is sent |
|--------------|-----------------|
| Member invitation | Admin invites someone to a workspace |
| Email verification | New account or email address change |
| Password reset | User requests a reset link |

When SMTP is not configured, the application still runs — email-dependent flows degrade gracefully and indicate that mail is unavailable.

## Verify it worked

1. Restart the SlugBase service after setting `SMTP_*` variables.
2. Trigger a password reset for a test account, or send a member invitation from **Settings → Administration → Members &amp; teams**.
3. Confirm the message arrives (check spam folders if needed).

## Troubleshooting

| Symptom | What to do |
|---------|------------|
| No email delivered | Verify `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, and `SMTP_PASS`. Check firewall rules for outbound SMTP from the container. |
| Messages land in spam | Configure SPF, DKIM, and DMARC for the domain in `SMTP_FROM`. |
| Workspace admin cannot edit SMTP | Expected — email is operator-managed. Update deployment environment variables instead. |
