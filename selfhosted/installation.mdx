## What you need

- **Git** and **Node.js** (Dockerfile and CI use **Node 20**).
- Network access to run `npm install` at the repository root (npm workspaces pull `backend`, `frontend`, `packages/core`, and `apps/selfhosted`).

This repository is an **npm workspace** monorepo. Day-to-day commands run from the root `package.json`; production serving for self-hosting uses the **`slugbase-selfhosted`** workspace via `npm run start`.

## Steps

<Steps>
  <Step title="Clone the repository" icon="git-branch" titleType="p">
    ```bash
    git clone https://github.com/mdg-labs/slugbase.git
    cd slugbase
    ```
  </Step>
  <Step title="Install workspace dependencies" icon="download" titleType="p">
    ```bash
    npm install
    ```

    This installs dependencies for all workspaces declared in the root `package.json`.
  </Step>
  <Step title="Choose how you will run SlugBase" icon="workflow" titleType="p">
    - **Local development:** `npm run dev` runs the backend and Vite frontend together (see [Quick start](/selfhosted/quick-start)).
    - **Production on bare metal or a VM:** `npm run build` then `npm run start` after you configure environment variables (see [Configuration](/selfhosted/configuration)).
    - **Production in Docker:** use the copy-paste **`docker-compose.yml`** on [Docker Compose](/selfhosted/docker-compose) with the published image—no git clone required—or pull **`mdglabs/slugbase`** / build from the root `Dockerfile` (see [Docker](/selfhosted/docker)).
  </Step>
  <Step title="Build for production (when not using Docker)" icon="hammer" titleType="p">
    ```bash
    npm run build
    ```

    The root build script builds the backend, frontend, core embed assets, and copies outputs needed by the self-hosted app.
  </Step>
  <Step title="Start production server" icon="play" titleType="p">
    ```bash
    npm run start
    ```

    This runs `npm run start` in the **`slugbase-selfhosted`** workspace—the combined API and static UI for self-hosted deployments.
  </Step>
</Steps>

## Verify

- After `npm run build`, the tree under `apps/selfhosted` and packaged `public` assets should exist without build errors.
- After `npm run start`, `GET /api/health` on your server port should return success (default port **5000** unless you set `PORT`).

<Callout kind="info">
  A **backend-only** image is also available as `Dockerfile.backend` for API-only deployments (for example serverless or split frontends). Most self-hosters use the full `Dockerfile` that bundles the built SPA under `public`.
</Callout>

## Troubleshooting

<ExpandableGroup>
  <Expandable title="npm install fails or workspace errors" default-open="false">
    Use a supported Node version (see **Node 20** above), delete `node_modules` only inside the repo if needed, and re-run `npm install` from the **repository root** so workspaces resolve correctly.
  </Expandable>
  <Expandable title="start fails with environment validation errors" default-open="false">
    The backend validates `JWT_SECRET`, `ENCRYPTION_KEY`, and production `SESSION_SECRET` before listening. Generate long random values and set `NODE_ENV=production` only when you intend to run in production mode. Details: [Configuration](/selfhosted/configuration).
  </Expandable>
</ExpandableGroup>
