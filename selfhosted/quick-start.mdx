## What you need

- **Node.js** compatible with the project (the production container images use **Node 20**).
- **npm** (workspace install at the repository root).
- For the fastest production tryout: **Docker** (see [Docker](/selfhosted/docker) or [Docker Compose](/selfhosted/docker-compose)).

<Callout kind="tip">
  New to deployment? After this page, follow [Docker Compose](/selfhosted/docker-compose), [Configuration](/selfhosted/configuration), and [First run setup](/selfhosted/first-run-setup) for a complete path.
</Callout>

## Steps

<Tabs>
  <Tab title="Local development" icon="code">
    <Steps>
      <Step title="Clone the repository" icon="git-branch" titleType="p">
        Clone the [SlugBase](https://github.com/mdg-labs/slugbase) repository and open the project root in a terminal.
      </Step>
      <Step title="Install dependencies" icon="download" titleType="p">
        ```bash
        npm install
        ```
      </Step>
      <Step title="Create a local `.env`" icon="settings" titleType="p">
        Before the backend can start, copy the repository template to `.env` at the project root (this tree ships `.env.example`; some checkouts use `example.env` for the same role). The server runs environment validation on every startup: `JWT_SECRET` and `ENCRYPTION_KEY` are required in development and production, not only when `NODE_ENV=production`. See [Configuration](/selfhosted/configuration) for the full list and how to generate safe values.
      </Step>
      <Step title="Start dev servers" icon="play" titleType="p">
        ```bash
        npm run dev
        ```

        This runs the backend and frontend together. By default you get:

        - Backend API: `http://localhost:5000`
        - Frontend dev server: `http://localhost:3000`
      </Step>
      <Step title="Complete initial setup in the browser" icon="user-plus" titleType="p">
        With a fresh database, the app shows **Initial Setup** so you can create the first admin user. Continue with [First run setup](/selfhosted/first-run-setup) for field requirements and what happens next.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Production (no Docker)" icon="server">
    <Steps>
      <Step title="Build the app" icon="hammer" titleType="p">
        From the repository root:

        ```bash
        npm run build
        ```
      </Step>
      <Step title="Set required secrets" icon="key-round" titleType="p">
        Before `npm run start`, define production secrets and URLs. The server validates `JWT_SECRET`, `ENCRYPTION_KEY`, and (in production) `SESSION_SECRET`. See [Configuration](/selfhosted/configuration) for the full list and safe values.
      </Step>
      <Step title="Start the self-hosted server" icon="play" titleType="p">
        ```bash
        npm run start
        ```

        The combined API and built frontend are served from the self-hosted app entrypoint (default port **5000**).
      </Step>
      <Step title="Open the app and finish setup" icon="rocket" titleType="p">
        Visit your server URL, complete **Initial Setup**, then sign in. Use [First run setup](/selfhosted/first-run-setup) as the checklist.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Production (Docker)" icon="container">
    <Steps>
      <Step title="Use Docker Compose with the published image" icon="container" titleType="p">
        You do not need to clone the repository: [Docker Compose](/selfhosted/docker-compose) gives you a **`docker-compose.yml`** to copy, **`mdglabs/slugbase:latest`** from Docker Hub, port **5000**, a **`./data`** volume for SQLite, and required **`.env`** secrets. Clone the repo only if you want to build from the **`Dockerfile`** instead. See also [Docker](/selfhosted/docker) for single-container options.
      </Step>
      <Step title="Verify health" icon="heart-pulse" titleType="p">
        The container health check expects HTTP **200** from `/api/health` inside the container.
      </Step>
    </Steps>
  </Tab>
</Tabs>

## Verify

| Goal | Check |
| --- | --- |
| Dev API up | Open `http://localhost:5000/api/health` (or your configured host) and confirm a successful response. |
| Dev UI | Load the frontend URL from Vite (default `http://localhost:3000`) and reach **Initial Setup** or login. |
| Production | Load your public origin; after setup you should reach the dashboard at `/`. |

## Troubleshooting

<ExpandableGroup>
  <Expandable title="Server exits immediately on start" default-open="false">
    Read the error output: every environment requires strong `JWT_SECRET` and `ENCRYPTION_KEY` (minimum length and no insecure defaults). In production only, `SESSION_SECRET` must also be set with sufficient length. See [Configuration](/selfhosted/configuration).
  </Expandable>
  <Expandable title="I see a blank page or API errors in dev" default-open="false">
    Confirm both processes from `npm run dev` are running and that the browser is pointed at the Vite dev URL for the UI. Check the backend terminal log for failed requests.
  </Expandable>
</ExpandableGroup>
